# E-commerce

Приложение для покупки товаров, реализованное с использованием микросервисной архитектуры.

## Общая архитектура

**Основные микросервисы**

1. Сервис Каталога (Catalog Service)

Функционал: Управление информацией о товарах (наименование, описание, цена, остатки).
Хранение данных: PostgreSQL.
API: Предоставляет REST и/или gRPC эндпоинты для:
Получения списка товаров.
Запроса детальной информации о товаре.
Проверки наличия товара перед добавлением в корзину.
Реализация: Использует userver для создания высокопроизводительного сервиса.

2. Сервис Корзины (Cart Service)

Функционал: Управление корзиной пользователя:
Добавление/удаление товаров.
Просмотр содержимого корзины.
API: Внешний REST API для фронтенда.
Взаимодействие: При добавлении товара делает запрос к Сервису Каталога для проверки его наличия.
Реализация: userver для обработки запросов и многопоточности для параллельной обработки операций.

3. Сервис Заказов (Order Service)

Функционал: Обработка оформления заказа:
Принимает данные корзины и формирует заказ.
Обновляет остатки товара в Каталоге (через API или прямой доступ к БД).
Передаёт информацию для последующих шагов обработки (например, оповещает склад).
API: REST/gRPC эндпоинты для создания заказа.
Взаимодействие: После создания заказа отправляет сообщение в очередь RabbitMQ.
Реализация: userver, что позволяет использовать gRPC для внутренней коммуникации и REST для взаимодействия с фронтендом.

4. Сервис Уведомлений (Notification Service)

Функционал: Рассылка уведомлений:
Оповещение клиента о подтверждении заказа.
Информирование других систем (например, склада) о необходимости обновления данных.
Механизм: Подписывается на сообщения из очереди RabbitMQ.
Реализация: userver для получения сообщений и отправки уведомлений (например, email, SMS).
